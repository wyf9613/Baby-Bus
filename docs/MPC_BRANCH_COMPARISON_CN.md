# 两个 MPC 分支的区别：`mpc-car-run` 与 `feature/mpc-model`

2026-10-20 整理。对比对象：
- **本分支** `mpc-car-run`：10-20 加入 feedback 模式之后。
- **Zhenyu 的分支** `origin/feature/mpc-model`：10-19 的 checkpoint `15724bc`，即 `checkpoint-user-good-motion-steer050`。

两边出自同一份 MPC 代码（`control-mpc-v0` 时期）。上一周各自在 5 号车上调试，朝两个方向发展：
- 本分支在**联合 MPC**（一个 QP 同时决定油门和转向）上，按 10-19 的实车包逐个补问题；
- Zhenyu 的分支把油门交给**轮速 PI**，MPC 只决定转向。

10-20 起，本分支把他的油门方案移植过来，作为可选模式 `mpc.longitudinal_mode: feedback`，具体见第 3 节。

## 1. 总览

| 方面 | 本分支（`mpc-car-run`） | Zhenyu（`feature/mpc-model` 15724bc） |
| --- | --- | --- |
| 油门 | 两种模式：`joint`（默认，QP 联合优化）；`feedback`（10-20 新增，轮速 PI，5 号车 `-fb` 包） | 轮速 PI + 基础油门，QP 里油门固定（`fixed_drive_request`） |
| 转向 | MPC | MPC |
| 转向预测用的车速 | `joint`：纵向模型；`feedback`：保持实测车速（`measured_motion`） | 保持实测车速（`speed_feedback_measured_motion`） |
| 车辆参数 | .27 的纵向拟合，加 5 号车 10-19 实测的死区 0.25 和转向 0.37 rad（`vehicle.valid: true`） | Gym 的力学参数（质量 3、电机 10、阻力 1、死区 0），`vehicle.valid: false`，靠 `gym_trial_acknowledged` 放行 |
| 转向区间 / 增益 | ±1.0，-0.37 rad（实测满舵 23–25°） | ±0.5，-0.3142 rad |
| 目标车速 | 0.20 | 0.25 |
| 超速 | 软线 / 切油门 / 0.40 硬停 | 超速锁停关闭（`overspeed_stop_enabled: false`），只靠 PI 收油 |
| 距离 / 时间上限 | 有 1 m、5 m 包；不限包两者都关 | 都关 |
| 估计 / 规划 | `ordered_xy` + `road_centerline` + lattice 2.1 | 相同 |
| 验证 | 本地测试 + WSL ROS 门禁 + 车包统计工具 | 本地测试 336 项（334 通过，2 项缺 osqp 跳过），ROS 门禁没跑通（缺 `dream_interfaces`） |

## 2. 逐项区别

### 2.1 纵向（油门）

**本分支 `joint` 模式。** QP 按纵向模型（死区、电机增益、阻力）选油门。10-19 在实车上逐项加了这些补丁：
- 偏置估计（`drive_bias`，±0.10）：吸收电量变化；
- 转弯阻力（`turn_drive_per_steer` 0.06）：舵量越大，死区抬得越高；
- 起步回差（`rest_speed_mps` 0.03）和起步后 0.5 s 的交接限幅（`handover_s`）；
- 按车速分两档的油门上限（`high_speed_drive_max` 0.35，切换车速 0.12）。

这些补丁各自有效，但都依赖模型准确。10-19 的车包仍然是"一段一段地走"：
- 起步后 2.5 s 内冲到软线的比例是 17/22；
- 跟踪阶段车速标准差 0.063，21% 的时间处在软线或切油门状态（`tools/car05_run_stats.py`）。

**Zhenyu：`speed_feedback_drive`。** 下面写成"基础油门 + PI"：
- 基础油门 `sustain` 0.30，kp 0.5，ki 1.0；
- 误差按"当前车速 + 加速度 ×（执行延迟 + 0.1 s）"预估，提前收油；
- 抗积分饱和，油门变化率限 2.0/s，油门上限 0.36；
- 起步脉冲 0.36，最多 0.5 s；执行延迟内先给"基础油门 + 0.04"；
- 车速低于 0.02 持续 2 s 时停车（`speed_feedback_motion_lost`）。

**本分支 `feedback` 模式。** 以他的 PI 为核心，改动见第 3 节。

### 2.2 转向与预测

两边转向的 QP 结构相同（RTI、线性化 `course_model_step`），区别在预测车速、转向参数和接口：

- **预测车速**：
  - Zhenyu：始终保持实测车速，油门只当作"维持当前车速"的数学量，不会发给车。
  - 本分支：`joint` 用纵向模型预测车速；`feedback` 在跟踪阶段保持实测车速；起步阶段两种模式都用纵向模型，因为车速为 0 时保持车速会让转向失去作用。
- **转向参数**：Zhenyu 在 ±0.5 的区间里用 0.3142（18°）。5 号车在 ±1.0 下实测满舵 23–25°，所以 ±0.5 时实际满舵只有约 12°，而模型按 18° 算。结果是 MPC 转向不足，急弯转不过去。他的文档也写了"急弯不能可靠跟随"。

### 2.2b 规划和 MPC 的转向假设是否一致（2026-10-20 核对部署配置）

| | 本分支（5 号车包） | Zhenyu（`ai4r_policy_lattice_feedback.yaml`） |
| --- | --- | --- |
| lattice 最大转向角 / 转向角速度上限 | **0.785 rad（45°）/ 1.57 rad/s**（基础配置默认值，没改） | **0.3142 rad / 1.21 rad/s，和他的 MPC 一致** |
| MPC 最大转向角 / 转向角速度上限 | 0.37 rad / 1.21 rad/s | 0.3142 rad / 1.21 rad/s |
| 车上转向区间（`traxxas_vehicle_interface.yaml`） | ±1.0 | **±0.5**（提交在他的分支里） |
| 车实际能转多少 | 0.40–0.44 rad（23–25°） | 约 0.21 rad（约 12°） |
| MPC 预测 / lattice | 都是 10 × 0.1 s = 1 s；lattice 都是 1 Hz、2.0 m | 同左，另有自适应时域 |

- **本分支**：lattice 按 45° 规划，最小转弯半径约 0.33 m；MPC 按 21° 跟，半径约 0.85 m。急弯时 lattice 可能给出 MPC 跟不了的路径，车偏离后路径检查失败、退回中心线，这可能是急弯入口切换和停车密集的原因之一（推测，未证明）。
- **Zhenyu**：规划和 MPC 一致（值得借鉴），但两者都按 18° 算，而车在 ±0.5 下只有约 12°，都高估了约 1.5 倍。
- **正确的做法**：三者对齐到实测值。车上 ±1.0；MPC 转向模型和 lattice 的 `steering_limit_rad` 都用实测满舵角（约 0.40–0.42 rad，或折中的 0.37）；`steering_rate_limit_radps` 统一 1.21。改 lattice 参数前先在 Gym 比较急弯，并告知 Planning 组。也可以只在 5 号车覆盖配置里改。

### 2.3 参考路径太短、起步、参考切换

| | 本分支 | Zhenyu |
| --- | --- | --- |
| 参考比预测时域短 | 沿最后一段直线外推，最多 0.3 m（`max_forward_extension_m`） | 自适应时域：按剩余路径缩短时域，最少 2 步，不够就减半重试 |
| 起步时接到路径上 | `ordered_lead_in` 拟合 | `start_bridge`：对齐检查 \|e_y\| ≤ 0.20、\|e_psi\| ≤ 0.35。他自己记录过这项检查导致停车（`start_bridge_alignment`） |
| lattice ↔ 中心线切换 | 中心线跳变保护（`switch_hold_s` 0.25）；切换后 0.4 s 内限制转向变化率（`switch_blend_s`） | 无 |

### 2.4 停车、卡住、读数过期

| | 本分支 | Zhenyu |
| --- | --- | --- |
| 轮速读数保持（车停了，驱动仍报最后读数约 3 s） | `WheelHoldMonitor`：读数 0.5 s 不变视为过期；结合 IMU 和舵量判断是否卡住；过期时冻结超速计时、偏置和 PI 积分 | 未处理。PI 会被不变的旧读数误导 |
| 卡住 / 掉速 | 回到起步阶段，重新给起步油门，最多重启 10 次（2 s 内的重复不计） | PI 积分继续往上加；2 s 无运动就停车 |

## 3. 移植了什么，改了什么（10-20）

| 他的部分 | 处理 | 原因 |
| --- | --- | --- |
| `fixed_drive_request`（QP 里固定油门） | 移植为 `solve(fixed_drive=...)`。超出上下限时夹到边界，不报错 | dense 和 osqp 两个求解器在上下限相等时都能正常求解（已测） |
| PI 核心 | 移植，**增益从 0.5/1.0 降到 kp 0.2 / ki 0.2** | .27 的拟合每单位油门约 10 m/s²，是他 Gym 参数的 3 倍；回路里还有约 0.4 s 延迟（0.26 s 执行延迟加上读数间隔）。kp 0.5 时，仿真里车速振荡，冲到切油门线 |
| 基础油门 | 取 `vehicle.drive_deadband`（0.25），**加上转弯阻力前馈** 0.06×\|舵量\| | 全靠积分吸收转弯阻力的话，出弯时多出的油门会把车推过软线，形成停走循环（仿真复现） |
| `measured_motion` | 移植，只在跟踪阶段生效 | 起步阶段车速为 0，保持实测车速会让转向失效 |
| 交接 | 起步 → 跟踪时，油门从起步油门开始按变化率下降，**积分保留已学到的值**；他是把积分反算到和起步油门一致 | 反算会把起步的冲劲延续下去（10-19 有 74% 的交接冲到了软线） |
| 读数过期 | **新增**：积分和油门都冻结 | 他没处理 |
| 软超速 | 保留：soft 时油门不超过基础油门，cut 时为 0，0.40 硬停不变；`-fb` 包的软线放宽到 0.10 / 0.05 | 在 0.05 / 0.03 下，切油门一下子降到 0，这本身会带出停走循环（仿真） |
| 按加速度提前收油 | **不移植** | 我们的轮速读数是阶梯状的（0.16–0.48 s 更新一次），差分出来的假加速度会把油门压到 0 |
| 起步脉冲、滑行锁存、2 s 停车判定 | 不移植 | 起步沿用我们在车上调好的起步油门（0.35，每秒加 0.05）；停车由卡住识别负责 |
| ±0.5 转向、`gym_trial_acknowledged`、关闭超速锁停 | 不移植 | 见 2.2 和第 1 节 |
| 自适应时域 | 暂不移植 | 和这次改动无关，以后单独评估 |

参数（`config/ai4r_policy_mpc_car05_feedback.yaml`）：

| 参数 | 值 |
| --- | --- |
| `longitudinal_mode` | feedback |
| `fb_kp` / `fb_ki` | 0.2 / 0.2 |
| `fb_sustain_drive` | 0（取死区） |
| `fb_integral_max` | 0.12 |
| `fb_slew_per_s` | 1.5 |
| `measured_motion` | true |
| 软超速 / 切油门余量 | 0.10 / 0.05 |

备用包：
- `-fb-nomm`：关闭 `measured_motion`，用来单独看它对转向的影响；
- `-fb-soft`：kp 0.15 / ki 0.1，车上 PI 振荡时换用。

`joint` 仍是默认模式，`joint` 包的行为不变。

**仿真依据（都只是仿真，不是实车证据）：**
- **纵向扫描。** 仿真车按 5 号车设置：死区 0.25、执行延迟 0.26 s、读数每 0.15–0.4 s 更新一次。另外故意让参数和模型对不上：
  - 转弯阻力 0.03–0.10；
  - 电量偏移 -0.03 到 +0.04；
  - 电机增益 ×0.7–1.4。

  在 54 种这样的仿真车上，kp/ki 0.2 下跟踪阶段零重启，车速波动 ≤ 0.017 m/s。剩下 4 次停车都发生在起步阶段（起步沿用原来的起步油门，`joint` 也一样）。
- **Dream Gym**（`car05_variants.py`，每组 60 次，0.20 m/s，仿真车转向 24°）：

  | 仿真车 | joint 完成 / 最高车速 | feedback 完成 / 最高车速 |
  | --- | --- | --- |
  | 死区 0.23，无转弯阻力 | 37 / 0.51 | 36 / 0.44 |
  | 死区 0.23，转弯阻力 0.06 | 38 / 0.43 | 36 / 0.34 |
  | 死区 0.289，无转弯阻力 | 31 / 0.39 | 30 / 0.38 |
  | 死区 0.289，转弯阻力 0.06 | 28 / 0.35 | 33 / 0.29 |

  - 所有组的控制层停车（超速、`no_motion`、`too_many_restarts`）都是 0；失败几乎都停在估计层（`invalid_ordered_geometry` 等），所以两种模式的完成率差别在噪声范围内。
  - feedback 的最高车速在每组都更低，有转弯阻力时尤其明显。

## 4. 需要和 Zhenyu 沟通

presentation 里怎么比（参数分三类对齐、两层对比）见 [MPC_COMPARISON_PLAN_CN.md](MPC_COMPARISON_PLAN_CN.md)。

1. **5 号车共用。** 部署时会互相覆盖配置，尤其是 `traxxas_vehicle_interface.yaml` 的转向区间（本分支要求 ±1.0，他的 checkpoint 是 ±0.5）。约定：每次上车先核对，用完恢复。
2. **把 5 号车实测转向告诉他**：±1.0 下满舵 23–25°。他的急弯问题很可能主要来自这里。
3. **他的 PI 会遇到读数过期的问题**，可以用本分支的 `WheelHoldMonitor`。
4. **增益。** 在 5 号车的实际油门响应下，kp 0.5 可能偏高。可以把本分支的扫描结果给他参考。
5. **M3 对比口径。** feedback 模式下 MPC 只负责转向，和 PID 组比的就变成"MPC 转向 + PI 油门"对"PID"。`joint` 保留作为原口径，需要组里确定用哪个。
