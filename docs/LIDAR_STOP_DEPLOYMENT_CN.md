# MVP2.1 雷达停车整合版

仅基于 `ying/lidar-stop-mvp21`，继承 MVP2.1 integration 分支；不是旧 V2 planner。
打包脚本直接读取当前公共配置，避免部署时再次手工抄写参数。

## 本版内容

- 目标速度 0.2 m/s；归一化 drive 前馈 0.30，上限 0.35。这些驱动值不是 m/s。
- 车头前沿间隙 <= 0.15 m 时请求零动作；直行走廊宽 0.30 m。
- base_link 到车头 0.275 m、到车尾 0.198 m。车头值包含约估的 7.5 cm 偏移，仍为暂定尺寸。
- 雷达 TF 应由车辆提供：base_link <- laser 为 x=0.200 m、z=0.120 m、yaw=180°；包不修改 TF 服务。
- 采集年龄上限 0.30 s，接收年龄上限 0.20 s，两者独立检查。
- 全帧 NaN、负无穷或越界距离不会再被视作有效空场景；保留原始扫描供诊断，Cartesian 不可用，启用门控时保护停车。
- +Inf 无回波与部分坏点仍受支持。此检查不保证每个方向都有有效覆盖，也不识别自车反射。
- 遇障碍、数据故障均锁存零动作；恢复数据或移开挡板不会自动重新开车，需要显式开始。
- 包含有界时效诊断、计算前后检查和监督停车；不更改规划/控制算法，不切换 executor 线程模型。

操作者报告旧时效修正版在 0.30/0.20 s 配置下已实车行驶并成功停车。
本版增加无效扫描修复并固定同一配置，仍需要重新核验其真实车辆行为。
没有测得的制动距离、实测车速、重复成功率或硬实时保证。

## 本地重新打包

在功能 worktree 运行，输出目录必须不存在：

```bash
.venv/bin/python tools/package_lidar_stop.py --output /绝对路径/新的部署目录
```

产物包含单文件 `policy_node.py`、完整公共 `ai4r_policy.yaml`、说明与 MANIFEST.json；
外层另有 tar.gz 和 SHA256 文件。manifest 记录源码/产物指纹、Git HEAD 与未提交状态。
打包不会测试、连接车辆或启动 policy；测试结果应另行核对。

## 以后部署时

先确认车辆静止、车辆接口 Disabled、policy 零动作，并结束当前 policy 运行。
将包中的两个同名文件安装到学生工作区 `scripts/policy_node.py` 和
`config/ai4r_policy.yaml`，再按课程 DREAM 流程构建、启动 policy。
启动应保持 publishing-zero；核对 enabled=true、0.30/0.20 s、15 cm、目标速度0.2。
先复验静止挡板、无回波、失帧与显式恢复，再进行现场受控行驶。
本包与打包工具均不发送车辆 Enable 请求。

## 时间读法

`max_source_age_s`：当前 ROS 时间距扫描 header.stamp 的上限；节点同时要求接收年龄不过期。
`max_receipt_age_s`：单调时钟距最后接纳扫描/对应点集的时间上限。
两个条件任一达到上限就保护停车；不是相加成0.50秒，也不是障碍出现后等待的时间。
10 Hz 扫描约每100 ms一帧；20 Hz控制/监督目标周期各为50 ms。
`last_policy_calculation_s` 记录最近一次估计/规划/控制计算耗时；不等于整个循环耗时。
监督与回调共享单线程 executor，长计算会延迟执行检查；当前没有硬实时保证。
`sensor_timeout_s` 的0.5秒是通用传感器期限，启用雷达门控后还要满足更短的上述期限。
所有这些都是数据和计算时间，均不等于物理刹停耗时。
