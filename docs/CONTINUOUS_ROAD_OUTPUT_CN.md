# 连续道路输出版本：实现和联调

2026-10-12，基于用户原分支 `feature/state-road-estimation` 的本地提交 `1b759ed`，新分支为 `feature/continuous-road-output`。原分支保留不变；本次未 push。沿用老师的单文件策略及现有配置文件，保留原规划算法、车辆参数和动作输出。不修改启动策略。

## 做了什么

仍由相机检测器提供锥桶坐标和颜色。有效新观测与已有锥桶融合；轮速和 IMU z 轴角速度分别经过原有样本感知一阶低通，在 ROS 时间上分段积分前进平面运动。每个策略周期用该运动把历史锥桶转到当前车体坐标。

相机短暂没有可用帧、拟合失败，或旧帧的总补偿跨度超过 0.3 秒时，新模式允许从已经逐周期移动的真实锥桶缓存重新拟合道路，继续输出当前参考时刻的中心线和双侧边界。它不是把上一帧坐标原封不动覆盖到当前帧，也没有重新把上一轮坐标按完整历史运动变换一遍。几何仍须通过原有 Huber、宽度、斜率、共同范围及车体原点覆盖检查。

这个版本是在原有传感器融合基础上补齐历史道路的输出，没有新增 KF/EKF、加速度积分、雷达匹配、全局地图或多套备用道路。最多保留 128 个历史锥桶，边界各最多 64 个，输出最多 201 点，仍为局部有限窗口。通常额外工作只是一次短区间积分；进入预测时额外拟合缓存。

## 期限与恢复

只有曾经得到完整、有效且覆盖原点的双侧道路，才允许短时预测。预测同时受以下限制，任一个先到就停止：

- 原有 `road_hold_s=0.2` 秒：从首次失败输出开始，0 禁用，最大允许 0.25 秒。
- 原有 `max_source_age_s=0.5` 秒：从最近接受的相机采集时刻开始，不从本次拟合时刻开始。
- 新增 `road_prediction_max_distance_m=0.2` 米：从最近接受的相机采集时刻起累计过滤轮速的行驶弧长，包含该帧处理延迟期间的运动。
- 历史点的原始寿命、双侧共同覆盖，以及每段连续轮速/陀螺仪的有效性。

每段仍遵守 0.15 秒运动源间隔和 0.3 秒单段积分跨度；新模式允许多段的总跨度超过 0.3 秒，不允许某一段没有数据。距离统计有独立的输出参考时刻，延迟帧把缓存放回相机坐标再融合时不会重复累计距离。使用弧长而不是净位移，因此转弯不能通过缩小净位移绕过距离预算。模型及轮速契约仍仅支持前进，不支持用无符号轮速推断倒车。

预测不会写入新的可信观测、刷新历史锥桶年龄或刷新相机融合时间。重复失败批次、反复缺帧以及中断后再次读取同一旧成功帧都不能重新起算延续期限。期限用尽后保留仍合格的锥桶供新帧恢复，但那个旧相机时刻不能重新开启预测；新的合格相机帧才能退出退化状态。

运动数据缺失/断档、时钟回退、未来/乱序帧、几何硬错误和观测冲突仍会拒绝预测并清理相应历史。预测能缓解短暂断续，不能保证持续单侧、严重噪声或长期缺帧时始终有路径。

## 时间和接口

原有内部 `self.estimation_output` 和道路字段保持：

| 字段 | 新模式中的含义 |
| --- | --- |
| `timestamp_s` | 当前道路所在车体坐标的参考时刻，与 `state.timestamp_s` 相同 |
| `measurement_timestamp_s` | 最近接受的真实相机采集时刻，预测期间不刷新 |
| `source_age_s` | 当前参考时刻减上述真实采集时刻，保留处理延迟 |
| `oldest_observation_timestamp_s` / `near_field.oldest_observation_age_s` | 所用锥桶中的最旧真实观测时间/年龄，多帧历史不冒充一次新测量 |
| `status=predicted_history` / `degraded=True` | 本次道路来自短时历史预测 |
| `current_frame` | 当前实际相机可用性、可见性、原始拟合质量；缺帧时不会显示成上一帧成功 |
| `prediction_remaining_s` | 源年龄、延续时间、历史寿命的剩余期限，并受当前速度下的剩余距离时间限制 |
| `prediction_distance_m` / `prediction_remaining_distance_m` | 已累计预测基准后的行驶距离与剩余距离预算，仅预测时提供 |
| `motion_compensation` | 从真实相机基准至当前的累计运动，增加 `travelled_distance_m`；预测中不是零时长伪补偿 |
| `fusion_mode` | 预测时为 `observed_cones_wheel_gyro_incremental` |
| `recommended_speed_scale=0.5` | 退化道路的减速建议，需规划/控制实际消费 |

无效道路不能使用；预测既不产生新的相机样本，也不改变锥桶原有颜色约定。轮速时间仍为 ROS 接收时刻代理，IMU/相机使用采集时间。采样延迟、轮速滑移、安装角和侧滑误差尚未实车标定。

## 当前配置和规划组需确认的内容

配置只增加 `continuous_road_output=true` 和距离上限，继续沿用原有延续时间等参数。类默认值为关闭，便于对比原模式。配置的单一执行触发改为 20 Hz timer，回调只收集观测；20 Hz 不代表相机达到 20 Hz。保持原相机新鲜度门限，并将轮速和 IMU 角速度列为必须新鲜的输入。任一必须传感器超时仍按课程框架停止并要求显式恢复，预测不会绕开该保护。

规划代码没有更改。规划组接入时需消费 `degraded`、减速建议和剩余时间/距离预算，每周期重新检查；`prediction_remaining_s` 的距离换算采用当前过滤速度，后续加速可能更快用尽距离，不是物理保证。若规划自身的源年龄门限更短，它仍会提前拒绝道路。旧 V1 的默认源年龄上限是 0.2 秒，且并未落实预测减速建议，所以本次只证明估计接口改善，不能宣称整车已经不会停车。字段是内部 Python 记录，本次没有建立新的 ROS 道路发布话题。

前后范围仍最多为车后 0.5 米、车前 3 米，实际输出取真实双侧共同有效范围，不保证每帧都有满长 3.5 米。首次启动时从未观测的近端道路不通过该模式补出，仍由规划组处理初始化。

## 离线证据

运行 `python3 -B tests/test_estimation.py` 与 `python3 -B tests/test_planning.py`：80 项估计检查、16 项规划检查通过。新增 14 项估计检查覆盖缺帧、长总补偿跨度、转弯、距离到期、处理延迟、旧帧不续期、恢复、时钟/数据故障、启动、无符号轮速拒绝倒车和有噪声连续帧的有界存储。

`python3 -B tools/study_continuous_road.py` 对实际基准/当前代码的纯估计定义进行同场景比较，原始结果在 `continuous_road_study.json`。直道和恒定转弯的相机暂停场景中，基准因总积分跨度限制产生的一次无效输出，新模式保持为明确标记的预测输出；新相机帧到达后恢复观测状态。该理想场景不用于断言真实道路精度。

每侧 64 锥桶的完整更新计时包含正常观测、缓存和预测，100 次重复、共每版本 1300 次更新；Windows Python 数据反映本机软件成本，不能直接当作车载 CPU 占用。完整 ROS gate、DDS/timer 和实车回放尚未运行，当前环境缺少 ROS 2 Jazzy、colcon 和已安装的 WSL。已更新配置加载的 ROS 检查，待课程环境执行。

该比较只显示额外计算的大致成本，不能根据一次 95 分位或最大值较低声称算法更快；新版本在预测周期多一次拟合，中位数明显增加。时间、距离到期和硬故障拒绝主要由自动检查覆盖，回放只展示规定短暂缺帧场景。
