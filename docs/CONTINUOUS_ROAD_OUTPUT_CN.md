# road-estimation-v2 感知接入 MVP2

2026-10-13 从 `origin/feature/road-estimation-v2` 的 `6552033` 选择性接入
`mvp2.0`（基线 `ae74be4`）。只替换 `EstimationSettings`、
`EstimationMotionHistory`、`EstimationPipeline`，以及对应感知配置和测试。
规划、控制、异步 worker、状态机和停车代码均保留 MVP2 原文。

感知每个策略周期通过轮速与陀螺仪移动真实锥桶历史，支持合并单侧新观测，
相机短时中断时可重新拟合历史道路。预测保持真实采集时间与原始锥桶年龄，
输出 `degraded`、减速建议及剩余时间/距离。未来帧、乱序帧、运动断档、
观测冲突和几何硬错误仍会拒绝相应道路。

当前感知 YAML 启用连续模式与距离历史：相机源年龄/框架超时 1.5 s，
空帧保护 2 s，失败后延续最多 0.8 s，预测累计行驶最多 0.5 m。
运动源间隔上限 0.25 s，单段积分上限 0.5 s；历史最旧观测上限 30 s，
局部窗口车后 1 m、车前 4 m。置信度、拟合、覆盖等门限采用来源分支配置。
这些是扩大接受范围的工程参数，未建立实车精度或漂移保证。

MVP2 规划仍保留 `max_source_age_s=0.4`、参考寿命上限 0.2 s、
近端缺口上限 0.9 m，以及原有预测减速/期限处理。估计器继续输出有效道路，
并不意味着规划会接受同样长的中断。首次启动没有已观测的近端支持时，
感知仍不外推道路；原 MVP2 的受控起步假设与检查继续适用。

用户随后明确选择将真正筛选路径的
`planning.lattice.hard_margin_m` 从 0.05 m 改为 0.02 m。
主恢复规划和次级 lattice 共用该参数，这是唯一额外规划配置变化。
车宽 0.25 m、前后车身尺寸、软净空 0.125 m、目标速度 0.2 m/s、
控制和 3 m/30 s 运行上限均保留。

用户随后选择所有场景使用 lattice：当前 YAML 设
`planning.lattice.centerline_first_enabled=false`，不再先运行中心线恢复/rollout。
`recovery_enabled=true` 保留原 MVP lattice 起步航向/偏航率范围，两个开关分离。
保留原采样集合、`max_candidates=16`、直接采样输出和异步执行；控制继续
消费 lattice 参考。这里 16 是候选上限，并非每帧必然生成/检查 16 条。
车身净空检查仍对实际生成的弯曲轨迹生效。

感知接入后、硬余量修改前，90 项估计、18 项规划、43 项 lattice、
42 项控制离线检查通过。新增感知→MVP2 检查通过，确认预测减速和原规划
0.4 s 源年龄门限仍生效。新增硬余量边界用例初跑失败后修正了测试输入和
调用参数；用户要求停止额外测试，修正后未重跑，最终完整 ROS gate 未运行。
实车结果与证据见 `acceptance.md` 及工作区 `diagnostics/mvp2-20261013/road-v2/`。
