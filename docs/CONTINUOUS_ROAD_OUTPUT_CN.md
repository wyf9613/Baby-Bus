# 连续道路输出版本：实现和联调

2026-10-12，基于用户原分支 `feature/state-road-estimation` 的本地提交 `1b759ed`，新分支为 `feature/continuous-road-output`。原分支保留不变；本次未 push。沿用老师的单文件策略及现有配置文件，保留原规划算法、车辆参数和动作输出。不修改启动策略。

用户要求优先连续输出后，当前 YAML 已切换为更宽松的连续性配置。初版连续输出提交 `af4aac7` 保留可对照，类默认参数也保留原值；下面的数值为当前启用的 YAML，不是老师规定的精度或实车标定结果。

## 做了什么

仍由相机检测器提供锥桶坐标和颜色。有效新观测与已有锥桶融合；轮速和 IMU z 轴角速度分别经过原有样本感知一阶低通，在 ROS 时间上分段积分前进平面运动。每个策略周期用该运动把历史锥桶转到当前车体坐标。

相机短暂没有可用帧、拟合失败，或旧帧的总补偿跨度超过配置的单段上限（当前 0.5 秒）时，新模式允许从已经逐周期移动的真实锥桶缓存重新拟合道路，继续输出当前参考时刻的中心线和双侧边界。它不是把上一帧坐标原封不动覆盖到当前帧，也没有重新把上一轮坐标按完整历史运动变换一遍。几何仍须通过 Huber、宽度、斜率、共同范围及车体原点覆盖检查，但当前对噪声、跨度和斜率的容忍更宽。

这个版本是在原有传感器融合基础上补齐历史道路的输出，没有新增 KF/EKF、加速度积分、雷达匹配、全局地图或多套备用道路。最多保留 128 个历史锥桶，边界各最多 64 个，输出最多 201 点，仍为局部有限窗口。通常额外工作只是一次短区间积分；进入预测时额外拟合缓存。

## 期限与恢复

只有曾经得到完整、有效且覆盖原点的双侧道路，才允许短时预测。预测同时受以下限制，任一个先到就停止：

- `road_hold_s=0.8` 秒：从首次失败输出开始，0 禁用，连续输出模式最大允许 1.0 秒；关闭连续输出时仍限 0.25 秒。
- `max_source_age_s=1.5` 秒：从最近接受的相机采集时刻开始，不从本次拟合时刻开始。
- `road_prediction_max_distance_m=0.5` 米：从最近接受的相机采集时刻起累计过滤轮速的行驶弧长，包含该帧处理延迟期间的运动。
- 历史点的原始寿命、双侧共同覆盖，以及每段连续轮速/陀螺仪的有效性。

每段仍遵守当前 0.25 秒运动源间隔和 0.5 秒单段积分跨度；新模式允许多段的总跨度超过 0.5 秒，不允许某一段没有数据。距离统计有独立的输出参考时刻，延迟帧把缓存放回相机坐标再融合时不会重复累计距离。使用弧长而不是净位移，因此转弯不能通过缩小净位移绕过距离预算。模型及轮速契约仍仅支持前进，不支持用无符号轮速推断倒车。

预测不会写入新的可信观测、刷新历史锥桶年龄或刷新相机融合时间。重复失败批次、反复缺帧以及中断后再次读取同一旧成功帧都不能重新起算延续期限。期限用尽后保留仍合格的锥桶供新帧恢复，但那个旧相机时刻不能重新开启预测；新的合格相机帧才能退出退化状态。

运动数据缺失/断档、时钟回退、未来/乱序帧、几何硬错误和观测冲突仍会拒绝预测并清理相应历史。预测能缓解短暂断续，不能保证持续单侧、严重噪声或长期缺帧时始终有路径。

## 时间和接口

原有内部 `self.estimation_output` 和道路字段保持：

| 字段 | 新模式中的含义 |
| --- | --- |
| `timestamp_s` | 当前道路所在车体坐标的参考时刻，与 `state.timestamp_s` 相同 |
| `measurement_timestamp_s` | 最近接受的真实相机采集时刻，预测期间不刷新 |
| `source_age_s` | 当前参考时刻减上述真实采集时刻，保留处理延迟 |
| `oldest_observation_timestamp_s` / `near_field.oldest_observation_age_s` | 所用锥桶中的最旧真实观测时间/年龄，多帧历史不冒充一次新测量 |
| `status=predicted_history` / `degraded=True` | 本次道路来自短时历史预测 |
| `current_frame` | 当前实际相机可用性、可见性、原始拟合质量；缺帧时不会显示成上一帧成功 |
| `prediction_remaining_s` | 源年龄、延续时间、历史寿命的剩余期限，并受当前速度下的剩余距离时间限制 |
| `prediction_distance_m` / `prediction_remaining_distance_m` | 已累计预测基准后的行驶距离与剩余距离预算，仅预测时提供 |
| `motion_compensation` | 从真实相机基准至当前的累计运动，增加 `travelled_distance_m`；预测中不是零时长伪补偿 |
| `fusion_mode` | 预测时为 `observed_cones_wheel_gyro_incremental` |
| `recommended_speed_scale=0.5` | 退化道路的减速建议，需规划/控制实际消费 |

无效道路不能使用；预测既不产生新的相机样本，也不改变锥桶原有颜色约定。轮速时间仍为 ROS 接收时刻代理，IMU/相机使用采集时间。采样延迟、轮速滑移、安装角和侧滑误差尚未实车标定。

## 当前配置和规划组需确认的内容

类默认值仍关闭新模式，便于对比原版；当前 YAML 开启并放宽连续性门限。单一执行触发仍为 20 Hz timer，回调只收集观测，20 Hz 不代表相机达到 20 Hz。相机新鲜度改为 1.5 秒，连续空帧保护改为 2 秒；轮速和 IMU 角速度仍要求新鲜，其框架超时保留 0.5 秒，实际估计更早受 0.25 秒运动年龄/历史间隔约束。超时仍停止并要求显式恢复。

| 连续性/几何参数 | 初版启用值 | 当前启用值 |
| --- | --- | --- |
| 失败后的延续时间 | 0.2 s | 0.8 s |
| 相机源年龄 / 框架相机超时 | 0.5 s | 1.5 s |
| 连续空检测保护 | 1.0 s | 2.0 s |
| 预测累计行驶距离 | 0.2 m | 0.5 m |
| 运动源间隔 / 单段积分跨度 | 0.15 / 0.3 s | 0.25 / 0.5 s |
| 锥桶原始年龄上限 | 20 s | 30 s |
| 局部窗口，车后 / 车前 | 0.5 / 3 m | 1 / 4 m |
| 最低检测置信度 | 0.5 | 0.25 |
| 最小有效覆盖 | 0.5 m | 0.3 m |
| 允许锥桶间隔 | 1.5 m | 2 m |
| Huber 尺度及 RMS 接受上限 | 0.08 m | 0.15 m |
| 合理道路宽度范围 | 0.4–2 m | 0.3–2.5 m |
| 最大局部斜率 | 1 | 2 |
| 本地规划源年龄配置 | 0.2 s | 1.5 s |

这些不是提高精度的参数，而是扩大接受范围和历史桥接期限。降低置信度及增大拟合容差，也会提高误检或错误道路通过的机会；本次没有用真实相机数据量化该代价。去重半径保留 0.08 米，增大它会误删相邻锥桶；滤波时间常数、采样间距、缓存点数上限和物理车辆参数不变。不能用非有限坐标、乱序时间、交叉边界或没有运动数据来换取连续 valid。

规划算法没有更改；本地 YAML 的规划源年龄同步为 1.5 秒，运动输入仍受单独更短门限约束。规划组接入时需消费 `degraded`、减速建议和剩余时间/距离预算，每周期重新检查；`prediction_remaining_s` 的距离换算采用当前过滤速度，后续加速可能更快用尽距离，不是物理保证。其他分支若仍用 0.2 秒源年龄会提前拒绝道路；本地 V1 仍未落实预测减速建议及预测剩余期限，且保留直线域及车身检查。这里只证明估计接口连续性改善，不能宣称整车不会停车。字段是内部 Python 记录，没有新增 ROS 道路发布话题。

前后范围当前最多为车后 1 米、车前 4 米，实际输出取真实双侧共同有效范围，不保证每帧都有满长 5 米。扩大窗口不扩大相机真实可见范围，也不会外推未观测的部分。首次启动仍由规划组处理初始化。

## 离线证据

运行 `python3 -B tests/test_estimation.py` 与 `python3 -B tests/test_planning.py`：90 项估计检查、16 项规划检查通过。保留全部初版检查，放宽门限后新增 10 项检查覆盖连续八个 10 Hz 失败帧的桥接、第九帧到期、超过一秒的缓存帧桥接、弱置信度、较短覆盖、较大边界噪声/锥桶间隔、扩大窗口、距离和源年龄到期，以及仍拒绝几何硬错误和运动断档。八帧成功不代表所有实车情况下都能保证八帧，速度、采集延迟和有效覆盖仍可能提前耗尽预算。

`python3 -B tools/study_continuous_road.py` 对实际基准 `1b759ed`、初版连续输出 `af4aac7` 和当前代码/当前 YAML 的纯估计定义进行同场景比较，原始结果在 `continuous_road_study.json`，记录源码、配置散列和实际参数。额外加入 0.8 秒相机暂停及连续空帧场景：各 21 个策略输出中，初版连续模式分别有效 15 / 10 个，当前配置均为 21 个；新帧恢复且原采集时刻保持正确。该理想场景不用于断言真实道路精度。

每侧 64 锥桶的完整更新计时包含正常观测、缓存和预测，100 次重复、共每版本 1300 次更新；Windows Python 数据反映本机软件成本，不能直接当作车载 CPU 占用。完整 ROS gate、DDS/timer 和实车回放尚未运行，当前环境缺少 ROS 2 Jazzy、colcon 和已安装的 WSL。已更新配置加载的 ROS 检查，待课程环境执行。
