# MVP2.1 雷达主动绕行：ROS 集成候选

此包是完整源码和配置候选，包含 MVP2.1、native planner、雷达候选筛选与执行
保护。规划在独立子进程运行，控制循环不等待规划求解。没有连接或启用车辆。

## 包内文件

- `policy_node.py`：包含各模块与 worker 的单文件入口，无需在车上复制 Python 模块目录。
- `ai4r_policy.yaml`：完整配置；不是需要手工叠加的参数片段。
- `MANIFEST.json`：源码、配置、产物指纹和 Git 来源。
- `说明.md`：本文件。外层另有 tar.gz 和 SHA256。

同时替换学生工作区 `scripts/policy_node.py` 与 `config/ai4r_policy.yaml`，
先保留车上的原文件，再按原 DREAM 学生工作区构建/启动流程运行。
不要只换其中一份。运行环境需要 ROS Jazzy、匹配的 dream_interfaces 和
`python3-numpy`；包不修改 DREAM、TF 服务或车辆驱动。

## 配置与行为

- 目标速度 0.20 m/s；MVP 的实车 drive 前馈和限制继承原整合版，没有使用仿真 0.004 前馈或负 drive 制动。
- 20 Hz 控制、2 Hz 后台规划请求、2.5 m 候选长度；worker 周期及交付耗时写入诊断。
- `lidar_avoidance.enabled=true`、`planner_control.enabled=true`、原雷达停车保护开启。
- 规划使用静态障碍记忆、全生成路径车身检查、曲率限制和绕行侧保持。
- 近直线感知中线只有在拟合残差不超过 2 cm 时才做直线平滑，实际观测边界继续作为硬约束。
- 感知余量始终为 8 cm；额外未来跟踪余量在前方 0.65 m 内从 0 增至 8 cm，不把已测得的当前位置误当作未来跟踪误差。
- 执行与中线 fallback 都检查最新雷达；通道阻塞、雷达失效、worker 故障或路径达到 1.5 s 都会停车。
- 正在绕行时，短暂的非阻塞重规划失败可以保留仍有效的旧路径；不刷新其原始时间，仍逐周期检查新雷达、道路、剩余覆盖和期限。
- 3.5 m 半径内的点进入有界静态记忆，最多 2048 个网格点；候选车身包络必须留在该范围内。
- 15 cm 是原车头间隙触发值；数据源年龄 0.30 s、接收年龄 0.20 s 独立检查，未放宽。
- 车头/车尾/车宽继承停车版 0.275/0.198/0.30 m，仍为暂定值；参数未绑定到某一辆车。
- 启动保持 state 2 / 零动作；所有锁存都只在有效数据下收到显式 state-3 请求后重置。

`planner_execution` 记录实际 planner/baseline 来源、绕行侧、记忆点数、停车原因。
`shadow_planning` 记录候选拒绝原因、输入时间、worker 源码指纹和实际交付耗时。
状态日志直接显示拒绝/停车原因，不需要根据小车是否移动猜测分支。

## 车上验证边界

软件验证与实车验证分开记录。此包尚未证明实际车辆的制动距离、安装尺寸、
转向曲率、动态障碍处理或硬实时能力。第一版针对低速静态障碍和道路空间足够
的场景；缺乏道路支持会停车，不会凭空补路。规划赶不上时也会停车。

车端安装时保持车辆静止和 Disabled，确认启动持续零动作，再按现场原有操作
流程进行受控低速验证。现场操作者负责 RC、Enable/Disable 和紧急停止；
此包从不发送车辆 Enable 请求。遇到误停应保留 `state_reason` 和两个诊断主题，
不要通过关闭停车保护或放宽传感器时效来强行启动。

重新打包：在本功能工作区执行 `python3 tools/package_lidar_avoidance.py --output 新目录`。
打包只写本地文件，不构建、不部署、不启动车辆。
