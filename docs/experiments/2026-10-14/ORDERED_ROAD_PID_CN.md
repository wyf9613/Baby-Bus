# 二维道路与 PID 急弯候选

缓弯实测基线已 push：`271bfb9`。本候选仍在本地 `fix/newcar-control`，未部署、未实车测试。
用户同意二维有序路径、记忆半宽单侧补线及调整末段补丁，要求保留 PID 和当前速度。

## 改动

- `estimation.road_geometry=ordered_xy`：按相邻距离和方向连续性组织锥桶链，支持竖直与折返。
  相邻间隔受绝对上限和局部锥桶间距约束，避免跨 U 弯空隙闭合到入口。
- 双侧沿局部法线配对，要求另一侧切线同向、匹配顺序连续和宽度有效。
  采用足够长的连续支持段，做一次有界局部平滑，再沿中心线自身弧长重采样。
- 单侧按上次双侧宽度的半宽法线偏移；远侧只有少数、不重叠的返回锥桶时继续近侧补线。
  新模式保留真实可见侧锥桶，单侧之后短暂全盲时可在原预算内推进曲线。
  不补造另一侧锥桶，不用预测或单侧数据重新学习宽度，不刷新来源年龄。
- `ORDERED_CENTERLINE` 使用 `s_m`；PID 预瞄沿道路前进 0.35 m，航向使用 `atan2`。
  最近路段排除相对车头反向的返回支路。继续使用横向 PI + 航向 P，未切换 Pure Pursuit。
- `control.mvp_error_filter_tau_s=0.10` 平滑当前控制误差，航向按最短角度方向平滑。
  手动停止、传感器失效和参考过期仍立即归零、清除滤波状态。
- 目标速度维持 0.2 m/s，速度 PI 0.35/0.08、油门前馈 0.30、上限 0.35；转向增益/限幅/变化率不变。
- `control.end_straight_distance_m=0.0` 关闭几何不足后的自动直行，避免急弯缺桶被当成终点。
  保留旧补丁实现；如需要终点补偿，后续应增加独立的终点触发依据。
- Foxglove 仍发布 `/car/policy_trajectory` 的标准 Path，原布局无需改动。

## 验证

完整 pinned Jazzy fast gate：**270 项，零失败、零错误、零跳过**。
其中 portable 181、ROS policy 84、colcon 5。检查覆盖左右 U 弯、有竖直路段的直角、
避免跳到近处反向出口、时间补偿、缺单侧/返桶、真实 Car 15 缺桶数据、
单侧后全盲预测的来源与期限、滤波及故障归零/轨迹清空。

理想自行车模型中的左右 1 m 半径 U 弯均走完，最大内部横向误差约 0.0484 m。
该模型假设轴距 L=0.33 m、归一化转向线性映射到 ±π/4、理想恒速/位姿，
不包含实际电调、舵机延迟、轮胎打滑、测量误差或视野遮挡。
两项额外源代码探针确认：未知半宽的单侧冷启动、双侧颜色顺序矛盾均拒绝。

初次完整检查中两个新增 ROS 用例使用 0.11 s 更新、默认参考寿命仅 0.10 s，正确触发停车。
将测试用例寿命显式设为生产值 0.20 s 后，focused 检查与最终完整 gate 通过。
日志及哈希见 `evidence/ordered-road/`。

## 上车与回退

上车只同步 `scripts/policy_node.py` 和 `config/ai4r_policy.yaml`，运行
`dream build ros student`，然后 `dream runtime restart ai4r_policy`。
包依赖没有新增。服务重启后策略从零输出开始，车辆 Enable 和策略 Run 仍分开操作。

临时选回旧几何/控制配置：`estimation.road_geometry=y_of_x`、
`control.mvp_error_filter_tau_s=0.0`，需要旧末段行为时设置 `control.end_straight_distance_m=0.8`。
完整旧版本以已 push 的 `271bfb9` 为准。

尚未校准实际最小转弯半径或车身扫掠范围。锥桶链是局部近似，分叉、稀疏布局造成的
拓扑歧义和长期无道路不在本次软件验证范围。实际直角/U 弯通过效果待实车记录。
