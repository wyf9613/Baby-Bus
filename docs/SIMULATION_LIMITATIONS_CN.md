## 道路感知与支路

- 感知按颜色生成 ordered_xy 边界链。同色锥桶可能来自不同道路支路，两种
  颜色同时可见不等于当前道路左右两侧均可见。
- 连续掉头的 7.25→7.30 s，车辆采集朝向跨过 90°，几乎同一串远支路蓝桶
  的世界排序翻转。蓝桶来自后续末段及感知延伸，黄桶来自当前第一个掉头。
  横向锥桶可以成链，但链方向、支路关联、内法线及双侧配对存在歧义。
- 配对冲突会返回空边界，并可通过默认 _clear_road_history 清除记忆宽度。
  已观察到连续左右掉头分别 67/68 帧两组锥桶成链却没有导出边界。
- 后期也会真正缺少一侧检测。相机为 80°、前向 4 m、最多 24 点；本次没有
  证据表明容量截断是导致整侧缺失的主要原因。现有单侧输出修复不解决串支路。

证据：[感知诊断报告](../offline/lattice_training/artifacts/2026-10-18-mvp-runtime-validation/PERCEPTION_DIAGNOSIS_CN.md)。

真值支路、未被检测的锥桶和场景宽度不能作为 policy/planner 的隐藏输入。

## 执行、控制与评估解释

- 实际 MVP 在首个有效动作之后提交规划。单边宽度未知而 baseline 无有效
  参考的静止启动可能在首次 native/policy 选路前停止；这不是模型选路失败。
- 历史随机道路的受控缺中线条件中，双侧边界仍在，但入口 baseline 可因
  `invalid_centerline_samples` 失败，使首次 native 作业和 policy 评分都尚未
  开始。policy 输入接口支持缺中线与整个系统能在缺中线时启动是两个不同
  条件。删除只作用于规划/选路输入，原感知曲线必须另存并在回放中标明。
- 规划生成成功不代表后续仍可执行；共享 execution 的滚动检查和 baseline
  回退保持生效。必须分别记录模型选路执行、baseline 和故障零指令。
- 当前 native 检查已知边界，baseline 没有避障响应。policy 可观察当前障碍，
  但只能选择已有且经 native 接纳的候选，不能补造缺失道路或不存在的候选。
- 冻结模型的标签来自统一 0.2 m/s 条件下的 C*；此次闭环使用真实 MVP PID。
  二者控制响应不同。目标速度不作为模型输入，此次不重训、不改变目标或增益，
  也不把 sigmoid(C* return) 当作成功概率或最高可行速度。
- common 参数在当前虚拟 plant 中曾产生约 0.776 m/s 启动峰值，目标仍为
  0.2 m/s。仿真到达终点、没有车身角点越界，不等价于遵守支路顺序的完整安全
  证明。跨支路问题仍需结合锥桶和道路可视化审查。
- 20 Hz 感知/control、1 Hz 生成与选择使用仿真时钟；固定 100 ms 交付为因果
  模型，真实 CPU 耗时另记。它不证明 ROS/实车调度、物理停车或硬件性能。

本次授权的 policy 接入范围是仿真 evaluation/可视化；ROS 主线入口和默认
native 执行不因此启用 learned policy。模型、输入编码、训练数据保持冻结。
