# 2026-10-21：sim 分支移植的离线对比（回放 + Gym）

计划：[docs/SIM_BRANCH_PORT_PLAN_CN.md](../../../docs/SIM_BRANCH_PORT_PLAN_CN.md)（含审阅修正）。分支 `mpc-car-run-sim-port`。

**所有结果都用固定 lattice 耗时（`--lattice-planning-s 0.10`），同一份代码重跑逐拍相同。** 以前的回放和 Gym 用本机实测耗时决定 lattice 结果哪一拍可见，同一份代码跑两遍回放 398 拍里有 355 拍不同、切换次数 12 对 10；所以 10-16（203/145/46）和 10-20 的数字本身带这部分波动，下面的数不能和它们逐个比，只能看趋势。

例外：本机很忙时 MPC 的 dense QP 也可能撞到求解时间上限（`solver_status: run time limit reached`），之后几拍有浮点级差别。10-21 在 Gym 并行时重跑 end-straight1 出现过一次（第 311 拍），汇总数字不变。

## 3. Gym 闭环（5 号车仿真车，`--plant-turn-drag 0.06`，联合 MPC，0.20 m/s，每组 60 次）

```bash
python offline/mpc_gym/car05_variants.py --plant-turn-drag 0.06 --seeds 6 --workers 7 \
    --lattice-planning-s 0.10 --set mpc.solver_time_limit_s=1.0 [--set ...] --json-out <out>.json
```

`mpc.solver_time_limit_s=1.0` 只用于离线：车上的 0.03 s 在本机忙时偶尔撞上，`plan_hold` 次数随负载变，同一组重跑 60 次里有 3 次不同。两项都固定后，结果确定：`tpw` 和 `tpw + colour auto` 在别的组并行跑的情况下仍逐行相同。

| 组 | 完成 | 直道 | 缓弯 | U 弯 | R1.5 | R1 | 急弯切换（U/R1.5/R1） | 最大横向（U/R1.5/R1，全部次） | 失败原因 |
|---|---:|---:|---:|---:|---:|---:|---|---|---|
| travel | 37/60 | 12 | 11 | 10 | 4 | 0 | 285 / 184 / 192 | 0.374 / 0.431 / 0.370 | 估计层 22，baseline_jump 1 |

| tpw + colour fixed，Gym 颜色对调（直道 4 次） | 0/4 | | | | | | | | `insufficient_common_range`（对照：对调确实生效） |

"估计层"= `invalid_road_*`（主要是 `invalid_ordered_geometry`），没有一次是规划层或 MPC 失败。

读法：
- **③ 不进 car05 配置。** `score_coverage: generated` 让横向误差更小（U 弯 0.144 → 0.099），切换不变，但完成从 33 降到 26（U 弯 9 → 4），多出来的全是估计层 `invalid_ordered_geometry`。结果确定，不是重跑波动；原因可能是车走的线不同、看到的锥桶不同，这里没有再追。按计划的通过标准（完成数在波动范围内）不通过。开环反号只少约 13%，也不足以抵消。保留选项（默认 `prefix`），结果交给 Planning 组。
- **② 不改变行为**：Gym 每次起步都同时看到两侧，第一帧就锁定，和 fixed 一拍都不差；颜色对调后 auto 照样逐行相同，fixed 全部停车。真实场地起步时只看到一侧、或者有别组锥桶的情况，Gym 覆盖不到，要用车包回放（WSL）。
